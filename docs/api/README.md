# Public REST API

For the Prasetya Webworks and Satamu Invitation integrations. The full contract is [`openapi.yaml`](openapi.yaml), and `tests/Feature/Api/OpenApiContractTest.php` fails if its paths drift from the routes.

## Conventions

**Base path:** `/api/v1`. Breaking changes need a new version.

**Success**

```json
{ "success": true, "data": {}, "meta": {}, "requestId": "01J..." }
```

**Error**

```json
{
  "success": false,
  "data": null,
  "error": { "code": "VALIDATION_FAILED", "message": "Data yang dikirim tidak valid.", "fields": { "customer.email": ["..."] } },
  "requestId": "01J..."
}
```

`requestId` is also the `X-Request-Id` response header, and appears in logs and audit rows. Quote it when reporting a problem. It is always generated by the server.

**Money** is integer rupiah: `{ "amount": 499000, "currency": "IDR" }`.

**Timestamps** are UTC ISO 8601.

## Idempotency

`POST /orders` and `POST /orders/{reference}/checkout` require an `Idempotency-Key` header of at most 128 characters. Generate one per user intent and reuse it on retry.

| Situation | Result |
|---|---|
| Same key, same request, finished | Original status, current state of the resource, `meta.idempotentReplay: true` |
| Same key, different request | 422 `IDEMPOTENCY_KEY_REUSED` |
| Same key, first request still running | 409 `IDEMPOTENCY_IN_PROGRESS` |
| First request failed | The key is released; retry with it |

A checkout is also safe across different keys: while an attempt is open, the same checkout is returned and DOKU is not called again.

## Price

The catalogue decides the price. `price`, `amount`, and similar fields in a request are ignored. Display `total.amount` from the response, not a value computed on the site.

## Rate limits and CORS

Reads 60 per minute per IP, mutations 10, webhook 120. Exceeding them returns 429 `RATE_LIMITED` with `Retry-After`.

Allowed origins come from `CORS_ALLOWED_ORIGINS`. A mutation from any other browser origin gets 403 `ORIGIN_NOT_ALLOWED`.

## Typical flow

```text
GET  /packages?application_code=WEBWORKS
POST /orders                         -> data.reference
POST /orders/{reference}/checkout    -> data.checkout_url, redirect the customer
     customer returns to the site's callback URL with ?order={reference}
GET  /orders/{reference}/payment-status   poll until PAID, or show the state
```

**A return from DOKU proves nothing.** Show the state from `payment-status` only. Notifications can arrive after the customer returns, so keep polling briefly on a pending result.

A reference can read the order, so the response leaves out customer contact details.

## Error codes

`VALIDATION_FAILED`, `NOT_FOUND`, `METHOD_NOT_ALLOWED`, `RATE_LIMITED`, `ORIGIN_NOT_ALLOWED`, `INTERNAL_ERROR`, `APPLICATION_NOT_FOUND`, `PACKAGE_NOT_FOUND`, `PACKAGE_INACTIVE`, `PACKAGE_APPLICATION_MISMATCH`, `IDEMPOTENCY_KEY_REQUIRED`, `IDEMPOTENCY_KEY_REUSED`, `IDEMPOTENCY_IN_PROGRESS`, `ORDER_NOT_PAYABLE`, `ORDER_ALREADY_PAID`, `CHECKOUT_IN_PROGRESS`, `GATEWAY_UNAVAILABLE`, `WEBHOOK_REJECTED`.
